# Maturity and limitations

Buzz and this fork are pre-1.0. A visible interface, kind constant, test fixture, or provider selector does not establish the same maturity as a complete production journey.

## Upstream-inherited boundaries

- Projects, workflows, Pulse, forum, and managed-profile behavior are registered as desktop preview features at the inherited baseline.
- Generic workflow executor paths remain incomplete even though definitions, triggers, runs, and approvals exist.
- Huddles, push, git hosting, remote agents, mesh compute, search, media, audit, and admin capabilities depend on deployment configuration.
- Mobile and web deliberately do not match desktop feature breadth.

## BUZZ — LIVE PREVIEW STUDIO boundaries

- Artifacts, reviews, and decisions are local to one renderer/device.
- A live URL is not a deployment, archive, or immutable content snapshot.
- Static site, deck, and film engines are accessible through deterministic E2E fixtures, not general production creation/import.
- Image/video generation wiring is provider-dependent and lacks recorded live-success evidence at the pinned baseline.
- Large imports use session-only object URLs.
- Native Android/iOS sessions, shared reviews, artifact relay events, and automatic agent feedback are proposed.
- The iframe manifest policy is not a complete network allowlist enforcement system.
- Public distribution still requires independent identity, signing, update, and branding work.
